# Community Mentorship and Peer-Learning Framework

## Purpose

This framework proposes a structured approach for helping student builders learn together, build practical projects, and gradually become contributors to open-source projects.

The goal is to create a supportive learning environment where beginners can start with small activities, learn from peers and mentors, and progressively take greater ownership.

## Objectives

The framework aims to:

- Help beginners get started with software development and open source.
- Encourage peer-to-peer learning and collaboration.
- Provide a structured path from learning to practical project building.
- Help students develop confidence in Git and GitHub workflows.
- Encourage participants to contribute to open-source projects.
- Create opportunities for experienced students to mentor newer contributors.

## Participants

The framework can involve three types of participants:

### Learners

Learners are students who want to improve their technical skills, build projects, and learn how to contribute to open source.

### Mentors

Mentors are experienced contributors or student builders who can guide learners, answer questions, review progress, and share practical knowledge.

### Community Coordinators

Community coordinators help organize learning activities, connect learners with mentors, collect feedback, and maintain the overall learning structure.

## Learning Path

A learner can progress through the following stages:

1. **Getting Started**
   - Understand the community and available resources.
   - Set up Git and GitHub.
   - Learn basic collaboration practices.

2. **Learning Together**
   - Join peer-learning sessions.
   - Work through beginner-friendly technical topics.
   - Ask questions and share learning resources.

3. **Building**
   - Choose a small practical project.
   - Work with peers where possible.
   - Document the project and development process.

4. **Contributing**
   - Learn how to identify beginner-friendly open-source issues.
   - Make documentation or small code contributions.
   - Create pull requests and learn from reviews.

5. **Giving Back**
   - Help newer learners.
   - Share knowledge and project experiences.
   - Progress toward becoming a mentor or community contributor.

## Peer-Learning Sessions

Peer-learning sessions can follow a simple structure:

1. Define the topic and learning objective.
2. Share useful resources before the session.
3. Begin with a short introduction to the topic.
4. Work on a practical example together.
5. Allow participants to ask questions.
6. Give participants a small task to complete.
7. Share the outcome and lessons learned.

The focus should be on active participation rather than only listening to presentations.

## Mentorship Approach

Mentorship should focus on guidance rather than doing the work for learners.

Mentors can:

- Help learners understand difficult concepts.
- Recommend learning resources.
- Review project progress.
- Provide constructive feedback.
- Explain Git and GitHub workflows.
- Encourage learners to solve problems independently.
- Help learners identify suitable open-source contribution opportunities.

## Project-Based Learning

Where possible, learning activities should lead to practical outcomes.

Examples include:

- Small software projects.
- Data analysis projects.
- Documentation improvements.
- Developer tools.
- Community resources.
- Open-source contributions.

Projects should be appropriately scoped so that beginners can make progress while still learning meaningful skills.
