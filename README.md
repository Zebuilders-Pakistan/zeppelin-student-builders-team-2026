## About

**Zeppelin Student Builders (ZeBuilders)** is a national student-builder community by **Zeppelin Labs Pakistan**.

We are building a network of university communities where students can:

- Learn software development
- Build real projects
- Contribute to open source
- Learn Git and GitHub
- Work with other developers
- Receive mentorship
- Share knowledge
- Develop leadership skills
- Build a public portfolio
- Create opportunities for other students

Our philosophy is simple:

> **Learn in public. Build real things. Contribute meaningfully. Help others build.**

This repository is for recruiting the **founding National Team of Zeppelin Student Builders — 2026**.

---

# Mission

> **To give university students in Pakistan a structured, mentored path into real software development through open-source contribution, peer learning, and direct exposure to how products are actually built.**

# Vision

> **To build a nationwide student-builder ecosystem where students across Pakistan learn by contributing to real software, grow through mentorship and community, and develop into contributors, leaders, and future builders.**

# Tagline

> **Building the next generation of developers through learning, mentorship, and open source.**

---

# Why Zeppelin Student Builders?

Many students learn programming primarily through:

- Courses
- Assignments
- Tutorials
- Certificates
- Small academic projects

But professional software development requires much more.

Developers need to learn how to:

- Read an unfamiliar codebase
- Use Git effectively
- Work with GitHub
- Understand issues
- Submit pull requests
- Review code
- Write documentation
- Communicate with contributors
- Work in teams
- Take ownership
- Build publicly
- Maintain software

Zeppelin Student Builders exists to create that bridge.

We want students to move from:

```text
Learning
   ↓
Building
   ↓
Contributing
   ↓
Collaborating
   ↓
Leading
   ↓
Helping Others Build
````

# Contribution-First Recruitment

Zeppelin Student Builders uses a **contribution-first selection model**.

We don't want to select people only because of:

* University name
* GPA
* Certificates
* CV length
* Social media followers
* Previous titles

Instead, we want to see what you can actually do.

Your GitHub contribution allows us to evaluate:

* Initiative
* Git/GitHub knowledge
* Problem solving
* Attention to detail
* Communication
* Ability to follow instructions
* Ability to work with an existing repository
* Ability to improve something
* Collaboration

> **We care more about meaningful contribution than contribution count.**

# Important Contribution Rule

Do not make meaningless changes.

The following are **not acceptable contributions**:

```text
Random punctuation changes
Unnecessary whitespace changes
Duplicate files
Spam PRs
Copied work
Artificial contribution inflation
Changes without meaningful purpose
```

We are evaluating **quality and intent**, not the number of lines changed.

# GitHub Contribution Guidelines

Before submitting your Pull Request:

1. Read the README.
2. Read `CONTRIBUTING.md`.
3. Check existing Issues.
4. Check existing Pull Requests.
5. Avoid duplicate work.
6. Keep your contribution focused.
7. Write clear commit messages.
8. Explain your contribution.
9. Test your changes where applicable.
10. Be respectful to other contributors.

# Frequently Asked Questions

## Do I need open-source experience?

No.

This recruitment process is designed to give you an opportunity to demonstrate your ability even if you are new to open source.

---

## Do I need to be an expert?

No.

We are looking for potential, initiative, and willingness to learn.

---

## Do I need to apply for a Lead role?

No.

You can apply as a National Team Member.

---

## Can I apply for multiple functions?

You can select a primary function and a secondary preference.

---

## Can I contribute to more than one area?

Yes.

Your primary function helps us understand where you can create the most impact, but collaboration across functions is encouraged.

---

## Can I submit multiple Pull Requests?

Quality matters more than quantity.

Do not submit unnecessary PRs.

One meaningful contribution is better than five meaningless ones.

---

## Does the Pull Request guarantee selection?

No.

The Pull Request is one component of the overall evaluation.

---

## Can I apply for Chapter Lead through this repository?

No.

Chapter-level recruitment will happen separately.

---

## Can graduates apply?

Yes.

Recent graduates are welcome to apply if they align with the objectives of Zeppelin Student Builders.

---

## What if I don't know what to contribute?

Start small.

Read the repository.

Look at open Issues.

Review existing documentation.

Identify something confusing, incomplete, broken, or improvable.

If you are still unsure, open a discussion or Issue before starting a large change.
